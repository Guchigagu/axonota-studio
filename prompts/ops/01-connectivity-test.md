# 模型连通性测试

## 何时触发
用户在设置里添加模型，点「添加模型」时，程序先用这条最小请求验证地址/Key/模型 ID 是否可用；失败就不进列表（§2.6 约定 4）。

## 变量

| 变量 | 含义 | 来源 |
|---|---|---|
| `{{model_id}}` | 用户填的模型 ID | 设置 |
| `{{base_url}}` | 用户填的服务商地址 | 设置 |

## 系统提示词

```text
这是一个连通性探测请求，不是对话。你只需要回复一个词：OK。
不要解释、不要提问、不要输出任何其他内容。
```

## 用户消息模板

```text
ping
```

## 请求参数（程序侧）

```json
{
  "model": "{{model_id}}",
  "messages": [
    { "role": "system", "content": "这是一个连通性探测请求，不是对话。你只需要回复一个词：OK。" },
    { "role": "user", "content": "ping" }
  ],
  "max_tokens": 8,
  "temperature": 0,
  "stream": false
}
```

## 成功判定

```text
HTTP 2xx 且返回内容包含 "OK"（大小写不敏感）。
只返回 4xx/5xx 或超时 → 视为失败，弹窗提示"这个地址或 Key 没有调通"，并保留用户已填内容便于修改。
```

## 隐私
- 本请求**不发送**用户任何笔记、附件或图片（§2.5 约定 1 的隐私说明依赖这一点）。
- 不记录本次请求的响应正文，只记成功/失败。

## 禁止
- 不用真实内容做探测（不要"用一段笔记试一下"）。
- 不因失败而自动重试超过 2 次（每次请求都由用户的服务商计费，不替用户多花）。
