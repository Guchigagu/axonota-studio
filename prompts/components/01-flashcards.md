# 闪卡组生成

## 何时触发
用户点快捷按钮「闪卡」，或自由输入"给我做 X 的闪卡"。组件类型由程序固定，AI 只填内容（§2.4 约定 10）。

## 变量

| 变量 | 含义 | 来源 |
|---|---|---|
| `{{source_scope}}` | 生成依据的范围（本章/全书/指定页） | 上下文范围 |
| `{{count}}` | 卡片数量，默认 10 | 用户指定，可为空 |
| `{{path}}` | 章节路径 | 结构 |
| `{{goal}}` | 该范围的学习目标 | 结构 |

## 系统提示词

```text
你生成闪卡：正面是问题，背面是答案。闪卡用于"合上书还能答出来"，因此考的是判断与回忆，不是复述原文。

硬规则：
1. 一卡一概念。正面只问一件事；背面 1–2 句，必要时加一个最小例子。
2. 正面禁止是非题（"X 是不是 Y"）；也不禁止"为什么"与"什么时候会坏"这类需要判断的问题。
3. 正面不出现答案关键词（背面答案里最重要的那个词不能在正面出现）。
4. 覆盖该范围的核心概念与常见坑；不要平均分配，把卡片集中在最容易错的地方。
5. 每条卡片带 tag（所属小节 id）；带公式的卡片在 back 里用 LaTeX，$...$ 包裹。
6. 不写"复习一下""记住"这类元话语。
7. 卡片之间不重复考点；同一考点最多 2 张（一张正面、一张反向）。
```

## 用户消息模板

```text
范围：{{source_scope}}
章节路径：{{path}}
学习目标：{{goal}}
卡片数量：{{count}}

请输出闪卡组 JSON。
```

## 输出 Schema

```json
{
  "type": "flashcards",
  "title": "2.3 用状态驱动界面 · 闪卡",
  "items": [
    {
      "id": "fc-1",
      "tag": "2.3",
      "front": "什么时候该把状态放在父组件而不是子组件？",
      "back": "当多个子组件要读同一份状态、或子组件的状态需要影响兄弟组件时，提升到最近的共同父级。只被一个子组件使用的状态不要上提。",
      "example": "列表与筛选框同读 keyword：keyword 放父级。"
    }
  ],
  "sources": [{ "index": 1, "kind": "local", "title": "第 2 章讲义.pdf", "locator": "p.12" }]
}
```

必填：`id`、`front`、`back`；`tag` 必须是对应的小节 id；`example` 可为空但字段必须在。

## 失败处理
- items 少于请求数量的一半 → 重试一次；仍少则返回实际数量并在 title 里标注"（部分生成）"。
- 正面出现答案关键词 → 程序不检测，靠本提示词约束；抽查发现后人工修。

## 禁止
- 不生成选择题。
- 不在 back 里写"见正文第 X 段"这类指向，闪卡必须自足。
