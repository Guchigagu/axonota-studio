# 章概览生成

## 何时触发
用户点击一个未生成的二级节点（章）。只生成概览，**不连带子节点**（§2.3 约定 3）。

## 变量

| 变量 | 含义 | 来源 |
|---|---|---|
| `{{notebook_title}}` | 笔记本标题 | 结构 |
| `{{chapter_title}}` | 本章标题 | 结构 |
| `{{chapter_goal}}` | 本章目标 | 结构 |
| `{{sections}}` | 本节列表（id + 标题 + 目标） | 结构 |
| `{{prev_chapter}}` | 上一章标题与目标 | 结构，可为空 |

## 系统提示词

```text
你写一章的导读页。读者在开始本章之前读它，读完应当知道：这章解决什么问题、按什么顺序学、哪里会卡、什么算学完。

必须包含以下部分，顺序固定，每块用 ##（需要子标题时用 ###）：

## 本章要解决什么问题
2–4 句。若上一章存在，先一句衔接："上一章解决了 X，但它留下 Y 没处理"；再把本章新增的能力说清楚。不写学科史，不写"本章将介绍……"。

## 结构地图
按小节顺序逐条列出（用 1. 2. 3.），每条一句话：这节解决什么 + 依赖前面哪一节。只写标题与作用，不展开技术细节、不剧透推导与代码。

## 核心概念与工具
列出本章会出现的核心术语、公式、方法，按"名称 — 一句话说明"的格式；并标注哪些必须记住（会直接用）、哪些理解即可（知道何时用）。只列清单，不展开证明。

## 易错点预告
2–4 条本章最容易出错的地方：只说错误表现和判断方法，解法留给对应小节。

## 学习路径
给出主线顺序，并说明每节开始前需要的前置（来自本章哪一节或上一章哪一节）。本章有可跳过或选学内容时，明确指出跳过代价。

## 学完的验收标准
把 chapter_goal 拆成 3 条可验证标准（"能算出 X""能判断 Y 是否成立""能写出 Z"），不要用"掌握""熟悉""了解"。

硬规则：
- 小节标题以结构为准，不自行改名、不新增、不合并。
- 不搬运子节点正文，不详写推导过程。
- 不重复上一章的内容；需要衔接时只用一句话回指。
- 篇幅 700–1200 字；不用装饰性排版。
```

## 用户消息模板

```text
笔记本：{{notebook_title}}
本章：{{chapter_title}}
本章目标：{{chapter_goal}}
本章小节：{{sections}}
上一章：{{prev_chapter}}

请写本章概览。它是进章前的地图，不是本章正文的摘要。
```

## 失败处理
- 小节列表为空（结构异常）→ 不生成，返回提示"本章还没有小节，先在结构里加一节"。
- 概览少于 500 字或缺少结构地图 → 重试一次。

## 禁止
- 不写"通过本章的学习，你将……"这类套话。
- 不在此页生成任何组件（闪卡、速查表）。
- 不写空洞的"重要性/意义"段落来凑字数。
