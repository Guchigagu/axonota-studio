# 来源与引用规则

## 作用
Axonota 的硬约束：任何 AI 产出都必须能回答"这是根据什么写的"。本段拼进所有需要来源的系统提示词。

## 正文（拼进系统提示词）

```text
来源分两类，必须分开：
- local：用户上传的资料（根文件、章节附件、图片）。本机文件，条目标题+文件名/页码。
- web：本次联网检索实际抓取成功的页面。必须给出真实 URL 与页面标题。

硬规则：
1. 只列实际抓取成功的网页。禁止凭记忆生成 URL、标题或作者；宁可不列，不可假列。
2. 无法核实的内容（模型知识、无来源推论）不分配编号，在句末写"（未核实）"。
3. 有 local 来源时，local 优先于 web。若 web 与 local 冲突，以 local 为准，并在冲突处写"注：网络资料与你的资料不一致，此处按你的资料写"，冲突处仍可同时给 web 编号。
4. 本次没有任何 local 资料时，正文第一行必须写：
   > 无上传资料，内容依据网络检索与模型知识，可信度较低。
   该标注由你在正文中输出，不要交给程序。
5. 联网关闭时，只能列 local；不得出现任何 web 条目，也不得暗示"我查过网上"。
6. 引用编号从 1 开始，按首次出现顺序编号，与文末 sources 数组顺序一致。同一段落内重复引用复用同一编号。
7. 不写"参考资料如下""以上内容引用自"之类的话，编号与 sources 由程序渲染。
```

## sources 数组结构（JSON 输出时使用）

```json
[
  { "index": 1, "kind": "local", "title": "第 2 章讲义.pdf", "locator": "p.12", "nodePath": "02 组件与状态" },
  { "index": 2, "kind": "web", "title": "React 官方文档 · State", "url": "https://react.dev/learn/state-a-components-memory" }
]
```

必填：`index`、`kind`、`title`；`kind=web` 必须有 `url`；`kind=local` 必须有 `locator`（页码或段落号）或 `nodePath`。

## 禁止
- 不把"模型内部知识"包装成 web 来源。
- 不重复列同一 URL。
- 不在正文里贴长 URL；正文只用编号。
