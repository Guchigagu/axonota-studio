# 上下文装配规则

## 作用
规定程序往提示词里塞什么、按什么顺序、超预算怎么砍。模型侧只需要知道"资料块长什么样、以及少了什么不要瞎猜"。

## 装配顺序（程序侧，按此拼用户消息）

```text
1. 任务指令（本功能文件的用户消息模板）
2. 结构上下文：祖先层级的标题路径（例：02 组件与状态 → 2.3 用状态驱动界面）
3. 根文件资料块
4. 祖先层级附件（仅当附件开关为「继承到下级」）
5. 本层附件
6. 本章已生成的其他小节正文（摘要形式，最多 3 段）
7. 网络检索结果（仅当联网开启且需要外部事实）
```

## 资料块格式（程序生成，模型只读不改）

```text
<<<local:根文件:chapter2.pdf|p.8-11>>>
（正文）
<<<web:react.dev/learn/state|2026-10-28>>>
（抓取的正文，已去导航）
```

## 预算与裁剪（按此顺序丢弃，直到低于预算）

```text
1. 网络检索结果（先砍最不相关的）
2. 本章其他小节摘要
3. 附件里的图片（保留图片文件名与一句话说明）
4. 祖先附件（从最远的祖先开始砍）
根文件与当前小节的相关段落永不裁剪；若仍超预算，先压缩根文件为摘录，并在开头标注"根文件已截断"。
```

## 高亮

```text
高亮是用户私有资产，默认不进入上下文。
只有在用户显式引用时（如"按我的高亮重写这段"），程序才会附带，并标记为 <<<user-notes>>>。
你不能假设自己看到了用户的高亮；没看到就不要提"你的高亮里提到"。
```

## 模型侧的注意事项（拼进系统提示词）

```text
- 资料块都是只读事实，不得改写后当成你自己的知识；引用时必须标注编号。
- 资料缺失（例如没有根文件、没有网络结果）时按既有知识作答，并遵守无资料标注规则；不要假装读过。
- 若资料块开头标了"已截断"，涉及被截断部分的具体事实时写明"资料已截断，未覆盖此部分"。
```
