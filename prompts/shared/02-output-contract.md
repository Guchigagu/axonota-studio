# 输出格式契约

## 作用
按调用类型取用对应小节，保证渲染器能稳定解析。正文类走 Markdown 子集；组件类必须是 JSON，且字段固定。

## A. 正文类（Markdown 子集）

```text
输出为 Markdown，遵守以下子集，渲染器只支持这些：
- 标题从 ## 开始，不用 #（页面已有一级标题）。最多到 ####。
- 段落之间空一行；不使用连续两个以上空行。
- 列表用 - 或 1.；嵌套不超过 2 层。
- 强调只用 **粗体**；不用斜体表达语气（斜体仅用于变量名与数学符号）。
- 代码用 ```lang 围栏，language 必须写（ts/tsx/js/json/bash/html/css）。
- 行内公式 $...$，独立公式 $$...$$，两者都必须能被 KaTeX 渲染；不要输出 \begin{align} 之外的复杂环境，不要用图片代替公式。
- 表格只用简单管道表格，首行必须是表头；单元格内不换行。
- 不输出 HTML 标签、内联 style、<br>。
- 引用标注写成 [[cite:1]]，编号对应 sources 数组下标（从 1 开始），同一句多个来源写 [[cite:1,3]]。
- 不写"参考文献"段落，来源由程序在文末按 sources 渲染。
```

## B. 组件类（JSON）

```text
只输出一个 JSON 对象，不包裹 Markdown 代码围栏之外的解释文字。
顶层必须是 {"type": "<组件类型>", "title": "...", "items": [...], "sources": [...]}。
- type 只能是：flashcards / glossary / custom_page。
- 不允许输出自由文本让程序去猜类型：类型错了，组件就渲染不出来。
- 字符串内不写 Markdown（除 glossary 的 formula 字段用 LaTeX）。
- sources 结构见 shared/03-sources.md；无来源时写空数组，不得省略字段。
- 所有必填字段缺失即视为本次生成失败，程序会重试一次，仍失败则展示"生成失败，可重试"。
```

## C. 流式规则

```text
流式只用于正文与对话回答。组件类不流式（半截 JSON 无法解析）。
流式开始时先输出一行 <meta>{"phase":"start"}</meta>，结束时输出 <meta>{"phase":"done","cites":[1,2]}</meta>，中间只有正文。
```

## D. 长度上限

```text
小节正文 1000–2000 字（短节可到 700）；章概览 700–1200 字；根概览 800–1300 字；对话回答 200–800 字（用户要求展开时不受此限）。
超限时优先删重复例子与铺垫，不删定义、推导步骤、结论与自检。
```

## 禁止
- 不输出"以下是为你生成的内容"这类前后缀。
- 不在 JSON 里夹注释。
- 不用表情符号或全角标点混排英文代码。
